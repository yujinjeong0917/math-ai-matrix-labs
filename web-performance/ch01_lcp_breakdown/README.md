# 1장 실습: LCP를 네 구간으로 나누기

가상 방문 하나의 LCP를 TTFB, 자원 로드 지연, 자원 로드 시간, 요소 렌더 지연으로 나누고 비율을 구해 web.dev의 상대적 권장 비율(약 40%, 10% 미만, 약 40%, 10% 미만)과 비교한다. 입력 시각에 따라 보고되는 LCP 후보가 바뀌는 것도 계산한다. 모든 시간은 가상, 예시용이다.

- 실행: `python3 lcp_breakdown.py`, 테스트: `python3 -m unittest -v` (표준 라이브러리만, 난수 없음)
- 기준값 출처: web.dev 문서(2026-11-20 확인, 정리해서 옮김, 문장 인용 아님). 4장의 논문 값은 저자 공개본 PDF(2026-11-20 확인).

손계산: 0.9+0.5+0.9+0.5=2.8초, 0.9/2.8=32.1%, 0.5/2.8=17.9%. 이미지를 줄인 경우 0.9+0.5+0.5+0.9=2.8초(로드 시간 -0.4초, 렌더 지연 +0.4초), 일찍 발견한 경우 0.9+0.1+0.5+0.5=2.0초. 후보 1.2초, 2.1초, 2.8초에서 입력이 없으면 2.8초, 2.0초에 스크롤하면 1.2초, 2.5초에 스크롤하면 2.1초가 보고된다.

기대 출력:
```
[처음] 비율 원값 [0.3214, 0.1786, 0.3214, 0.1786]
[처음] 구간 [0.9, 0.5, 0.9, 0.5] 합 2.8초 -> 2.5초 초과
[처음] 비율 [32.1, 17.9, 32.1, 17.9]%, 지침과의 차이 [-7.9, 7.9, -7.9, 7.9]%p, 가장 긴 구간 TTFB · 자원 로드 시간
[이미지 줄임] 비율 원값 [0.3214, 0.1786, 0.1786, 0.3214]
[이미지 줄임] 구간 [0.9, 0.5, 0.5, 0.9] 합 2.8초 -> 2.5초 초과
[이미지 줄임] 비율 [32.1, 17.9, 17.9, 32.1]%, 지침과의 차이 [-7.9, 7.9, -22.1, 22.1]%p, 가장 긴 구간 TTFB · 요소 렌더 지연
[일찍 발견] 비율 원값 [0.45, 0.05, 0.25, 0.25]
[일찍 발견] 구간 [0.9, 0.1, 0.5, 0.5] 합 2.0초 -> 2.5초 이하
[일찍 발견] 비율 [45.0, 5.0, 25.0, 25.0]%, 지침과의 차이 [5.0, -5.0, -15.0, 15.0]%p, 가장 긴 구간 TTFB
[보고되는 LCP] 입력 없음: 2.8초 대표 상품 이미지
[보고되는 LCP] 2.0초에 스크롤: 1.2초 상품명 텍스트 블록
[보고되는 LCP] 2.5초에 스크롤: 2.1초 배너 이미지
[점검 1] 구간 [0.8, 0.2, 1.0, 0.4] 합 2.4초, TTFB 비율 33.3%
[점검 3] 2.3초에 탭하면 보고되는 LCP 2.1초 배너 이미지
```

확인하지 못하는 것: 권장 비율은 문서가 지침이지 목표가 아니라고 한 값이고 실측 평균인지는 확인하지 못했다. 네 구간의 시작과 끝 경계 정의, 입력 시각과 후보 시각이 같은 순간의 처리는 원문으로 확인해야 한다. 개선 방법이 몇 퍼센트 줄이는지는 문서에 수치가 없어 계산하지 않는다.
