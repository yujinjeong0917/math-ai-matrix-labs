# 0장 실습: 세 지표를 기기별 75번째 백분위로 판정하기

가상 상품 목록의 방문 기록으로 LCP, INP, CLS를 모바일과 데스크톱으로 나눠 75번째 백분위를 구하고 web.dev가 권고하는 기준(LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하)과 대조한다. 모든 숫자는 가상, 예시용이다.

- 실행: `python3 vitals_verdict.py`, 테스트: `python3 -m unittest -v` (표준 라이브러리만, 난수 없음)
- 기준값 출처: web.dev 문서(2026-11-20 확인, 정리해서 옮김, 문장 인용 아님). 4장의 논문 값은 저자 공개본 PDF(2026-11-20 확인).

손계산: 모바일 LCP 10번을 작은 순서로 세우면 1.9 2.0 2.1 2.2 2.3 2.4 2.6 2.9 3.3 3.8초이고 올림(0.75 x 10) = 8번째 값이 2.9초(2.5초 초과). 데스크톱 8번째는 1.8초. 두 기기를 합친 20번은 올림(0.75 x 20) = 15번째 값 2.4초라서 합치면 모바일의 미달이 가려진다. 모바일 INP 240ms는 개선 필요, CLS 0.08은 좋음이므로 모바일은 통과가 아니다.

기대 출력:
```
[모바일] LCP p75 2.9초(좋음 아님), INP p75 240ms(개선 필요), CLS p75 0.08(좋음) -> 통과 아님
[데스크톱] LCP p75 1.8초(좋음), INP p75 120ms(좋음), CLS p75 0.04(좋음) -> 세 지표 모두 좋음
[LCP 모바일 정렬] [1.9, 2.0, 2.1, 2.2, 2.3, 2.4, 2.6, 2.9, 3.3, 3.8]
[LCP 데스크톱 정렬] [1.2, 1.3, 1.4, 1.5, 1.5, 1.6, 1.7, 1.8, 2.0, 2.6]
[LCP 2.5초 초과 비율] 모바일 40%, 데스크톱 10%
[합친 20번] 정렬 [1.2, 1.3, 1.4, 1.5, 1.5, 1.6, 1.7, 1.8, 1.9, 2.0, 2.0, 2.1, 2.2, 2.3, 2.4, 2.6, 2.6, 2.9, 3.3, 3.8]
[합친 20번] ceil(0.75 x 20) = 15번째 값 = LCP p75 2.4초(좋음)
```

확인하지 못하는 것: 백분위는 올림 순위 방식이다. 기다림 트랙 0장은 선형 보간을 써서 값이 조금 다를 수 있고, web.dev가 어느 방식을 쓰는지는 확인하지 못했다. INP와 CLS의 p75는 대시보드가 보여 준 값이라고 가정해 입력으로 받았다. LCP의 나쁨 기준(4.0초 초과)은 문서 본문이 아니라 그림 설명에서만 확인해서 판정에 쓰지 않았다. 사용자가 느낀 속도, 이탈, 전환은 계산하지 않는다.
