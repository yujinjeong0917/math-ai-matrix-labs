# 1장. 파인튜닝이 필요한 때: 프롬프트·RAG와 무엇이 다를까 (`ch01_when_finetune`)

웹 챕터: `math-ai-matrix/tracks/finetune/01-when-finetune.html`

관통 프로젝트("AI 도구 실전" 트랙의 가상 팀이 고객 문의 답변 초안 모델을 직접 만든다)의 첫 단계. 같은 문의 40건에 프롬프트 고치기(P), 검색해서 붙이기(R, RAG), 파인튜닝(F)을 대 보고, 실패 종류마다 무엇이 남는지 GPU·네트워크·API 키 없이 센다.

1. 토큰 예산: 예시 k개를 넣은 호출 길이 `s + k·e + q`와, 문맥 창에 들어가는 예시 수의 최댓값 `k_max`.
2. 검색기: 한국어 글자 바이그램 겹침으로 정책 문서 8개 가운데 1등을 고른다. 동의어("공짜"와 "무료")는 못 찾는다.
3. 비교 모형: 방법 × 실패 종류 규칙(`data/fix_rules_2026-10-11.json`, 칸마다 근거 URL 또는 [가정])에 문의 수를 곱해 남는 실패를 센다. 계산으로 정해지는 칸은 P×T(토큰 예산), R×K(검색 적중), F×K(지난 답변 횟수, 정책 변경 뒤 옛 값) 셋이다.
4. 정책 변경: 환불 기한과 무료 배송 기준이 바뀐 v2에서, v1로 학습한 파인튜닝이 옛 값으로 답하는 문의를 센다.

## 실행
```bash
uv run python finetune/ch01_when_finetune/experiments.py   # results/ch01.json 갱신
uv run pytest -q finetune/ch01_when_finetune
```
표준 라이브러리만 쓴다. 무작위가 없어 결과가 매번 같다.

## 한계
- 실패 이름표, 규칙 표 15칸 중 9칸, 토큰 수, 지난 답변 횟수, "말투에 예시 100개 필요", "3번 이상 나온 사실만 배운다"는 모두 정한 값이다. 결과 표는 이 가정 위에서만 맞다. E6에서 횟수 기준을 1~6으로 바꿔 보면 파인튜닝만 썼을 때 남는 실패는 4~8건으로 움직이지만, 정책 변경 뒤 옛 값으로 틀리는 답은 4건 그대로다.
- 실제 모델을 돌리지 않았다. 파인튜닝에 드는 데이터 준비, GPU 시간, 다시 학습하는 비용은 이 모형에 없다(5·8장).
- 검색기는 일부러 단순하다. 임베딩 검색이나 동의어 사전을 쓰면 적중이 달라진다.
- R과 F를 함께 쓸 때 "붙인 문서를 따른다"는 충돌 규칙은 가정이다.
