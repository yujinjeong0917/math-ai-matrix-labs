# 11장 · 재시도가 같은 문의를 두 번 처리하면 어떻게 하나요?

한 작업자가 메시지를 묶음으로 받아 차례로 처리할 때 가시성 제한 시간 때문에 다시 보이는 메시지 수, Lambda 비동기 호출의 최대 실행 횟수, 멱등 키 유무에 따른 부작용 횟수, SQS FIFO의 5분 중복 제거 구간을 모형으로 계산합니다. AWS 호출은 없어요.

## 실행

```bash
python3 retry_sim.py retry_profile.json
python3 -m unittest -v
```

## 기대 출력

```
묶음 10건, 건당 25초, 제한 시간 30초
  완료 시각: [25, 50, 75, 100, 125, 150, 175, 200, 225, 250]
  다시 보이는 메시지 9건 (순번 [2, 3, 4, 5, 6, 7, 8, 9, 10]), 낭비 계산 225초
  느린 건(40초) 기준으로 필요한 제한 시간 400초
Lambda 비동기 기본 실행 횟수: 최대 3번
10건에 중복 3건이 섞였을 때 부작용: 멱등 없음 13번, 멱등 키 10번
FIFO 5분 구간: 5번 보내서 3건 수락 [(0, 'req-1'), (300, 'req-1'), (310, 'req-2')]
```

## 이 실습이 확인하지 못하는 것

- 첫 번째 묶음만 따라갑니다. 다시 보인 메시지가 다음 묶음에 섞이는 연쇄는 계산하지 않아요.
- FIFO 구간의 경계(정확히 300초)는 문서에서 확인하지 못해 모형의 선택입니다.
- 멱등 키 기록소는 메모리 집합이에요. 실제로는 작업자가 죽어도 남는 저장소가 필요합니다.
- SageMaker 비동기 추론의 재시도 규칙, Lambda 최대 재시도 설정의 허용 범위는 확인하지 못했어요.
- 환불 중복 사례는 사이트의 에이전트 만들기 4장(`/tracks/agent-build/04-double-refund.html`)을 보세요.
