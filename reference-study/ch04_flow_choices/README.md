사이트의 세 화면(홈, 학습 트랙 목록 화면, 트랙 장 화면 06번)에서 `<main>` 안 `<a href>`를 파서로 뽑아 저장한 스냅샷(`links_snapshot_2026-11-18.json`)을 읽어, 링크 수를 구분해 세고 홈에서 장 화면까지 최소 걸음 수를 너비 우선 탐색으로 계산합니다. 이 폴더의 코드는 사이트 파일을 읽지 않고 스냅샷만 읽습니다. 파이썬 표준 라이브러리만 씁니다.

스냅샷은 일회성 스크립트로 만들었고, 이 폴더에는 JSON만 둡니다. 스냅샷에는 화면 파일의 sha256과 크기, 링크 하나하나의 원래 `href`와 분류(`same_page`, `external`, `internal`)와 해석된 주소가 들어 있습니다.

## 실행

```bash
python3 flow.py
python3 -m unittest -q
```

## 읽는 법

- "같은 화면 #"은 화면 안에서 위치만 옮기는 링크(`#math` 등)라 사이트 안 링크에서 뺐습니다. "외부"는 사이트 밖 주소입니다.
- "고유 주소"는 사이트 안 링크에서 같은 주소(`#` 뒤 조각 포함)를 한 번만 센 값입니다.
- 링크 수는 선택지의 상한입니다. 사람이 실제로 비교하는 선택의 수가 아닙니다.
- 최소 걸음은 스냅샷에 담은 세 화면에서 나가는 선만 따라가서 구합니다. 홈에서 장 화면로 가는 직접 링크가 없다는 것도 같은 스냅샷으로 확인합니다.

## 이 실습이 확인하지 못하는 것

- 링크 수는 선택지의 상한입니다. 사람이 어디서 망설이는지는 재지 않았습니다. 사용자 관찰이나 행동 기록이 필요해요.
- 세 화면만 담았습니다. 전역 메뉴(`<main>` 밖), 검색, 다른 화면에서 장으로 가는 길은 넣지 않았습니다. 그래서 "최소 2걸음"은 홈 HTML 어디에도(메뉴와 푸터 포함) 장 화면 주소가 없다는 사실과 학습 트랙 목록 화면에서 장으로 가는 링크가 있다는 사실에서 나온 정적 HTML 기준의 값입니다. 자바스크립트가 만드는 링크와 메뉴 패널을 거치는 길은 따라가지 않았습니다.
- 장 화면 값은 06번 한 화면의 값이고 장마다 다를 수 있습니다.
- 스냅샷은 2026-11-18의 파일입니다. 파일이 바뀌면 숫자도 달라지므로 스크립트를 다시 돌려 새 날짜의 스냅샷을 만들어야 합니다.
