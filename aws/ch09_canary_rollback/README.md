# 9장 · 새 모델은 몇 건을 보고 나서 전체로 바꿔야 할까요?

새 모델을 일부 요청에만 먼저 보낼 때 필요한 노출 건수, 경보 기준의 오경보·감지 확률, 두 묶음이 함께 켜지는 시간을 계산합니다. AWS 계정과 비용이 드는 리소스는 만들지 않아요. 가격은 다루지 않습니다.

## 실행

```bash
python3 canary_sim.py canary_profile.json
python3 -m unittest -v
```

(pytest가 있으면 `python3 -m pytest -q`도 돌아갑니다.)

## 기대 출력

```
하루 요청 20건, 카나리 5%: 새 모델 노출 1.0건/일
하루 요청 20000건, 카나리 5%: 새 모델 노출 1000건/일
나쁜 답 2%를 95% 확률로 보려면 노출 149건 필요
나쁜 답 10%를 95% 확률로 보려면 노출 29건 필요
하루 20건에서 149건 모으는 데 149.0일
하루 20000건에서 149건 모으는 데 3.6시간
50건 노출 때 나쁜 답 2%를 하나 이상 볼 확률 0.636
창 50건, 4건 이상이면 경보: 정상 모델 오경보 0.018, 나쁜 모델 감지 0.750
하루 20건에서 29건 모으는 데 29.0일
하루 20000건에서 29건 모으는 데 41.8분
경보 창 50건이 차는 데: 하루 20건 50.0일, 하루 20000건 72.0분
연속 두 창 모두 울려야 경보: 오경보 0.0003, 감지 0.562
연속 두 창 중 하나만 울려도 경보: 오경보 0.035, 감지 0.937
별칭 가중치: {'first_version': 0.95, 'additional_version': 0.05}
두 묶음이 함께 켜진 시간 하한: 1200초
```

## 채울 값

`canary_profile.json`의 비율(기존 모델이 평소 내는 나쁜 답 2%, 새 모델이 낼 수 있는 나쁜 답 10%·2%)과 경보 창(50건, 4건)은 가상 숫자입니다. 내 평가 세트에서 잰 값으로 바꾸세요.

## 이 실습이 확인하지 못하는 것

- 실제 AWS 호출은 하지 않습니다. 트래픽 이동·경보·자동 되돌리기가 실제로 동작하는지는 보지 못해요.
- 나쁜 답이 요청마다 독립이라고 가정합니다. 질문 유형별로 다르면 필요한 건수가 늘어요.
- 새 묶음이 뜨는 시간은 포함하지 않은 하한값입니다.
- 가격과 한도는 코드에 고정하지 않았습니다. 확인한 한도와 URL은 장 본문의 표(2026-11-14 확인)에 있어요.
