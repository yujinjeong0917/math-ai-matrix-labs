# 2장. 같은 앞부분을 또 보내면 왜 돈이 덜 들까 (`ch02_api_caching`)

웹 챕터: `math-ai-matrix/tracks/tools/02-api-caching.html`

관통 프로젝트(가상의 작은 팀이 만드는 "주간 고객 문의 요약 보고서")에서, 지시문 + 예시 + 이번 주 문의 묶음(약 3만 2천 토큰, 가정값)을 API로 12번 보낼 때 비용이 어떻게 나오고 프롬프트 캐싱으로 얼마나 줄어드는지를 네트워크·API 키 없이 재현한다.

1. 요청 메시지(JSON)의 칸을 한 줄씩 읽고, SDK가 대신 해 주는 일(키 읽기, 머리글, 필수 칸 확인, 재시도)을 작은 흉내로 확인한다.
2. 캐시 쓰기 배율 w, 읽기 배율 r로 손익분기 호출 수 n*를 계산하고, 공급사 문서가 스스로 적은 숫자(1번/2번 읽기, 1.35배, 221토큰)를 다시 계산한다.
3. 앞부분 캐시를 블록 단위로 흉내 내 캐시가 깨지는 흔한 실패 8가지(앞에 시각·이름, 질문을 앞에, 바뀌는 블록에 캐시 지점, 유지 시간보다 긴 간격, 최소 토큰 미만)를 비교한다.

## 실행
```bash
uv run python tools/ch02_api_caching/experiments.py   # results/ch02.json 갱신
uv run pytest -q tools/ch02_api_caching
```
표준 라이브러리만 쓴다(fractions로 금액을 정확히 계산). 실제 API를 부르지 않는다.

## 파일
| 파일 | 역할 |

| `tools_ch02_cache.py` | 가격표 읽기, 손익분기, 앞부분 캐시 흉내(PrefixCache), usage → 금액(Anthropic·OpenAI 두 모양) |
| `tools_ch02_request.py` | 요청 메시지 블록 펼치기, SDK 흉내(MiniClient)와 가짜 전송(FakeTransport) |

## 가격을 바꿀 때
`data/prices_YYYY-MM-DD.json`을 새로 만들고 `tools_ch02_cache.PRICE_FILE`을 그 파일로 바꾼 뒤 실험과 테스트를 다시 돌린다. Gemini 3.8 Flash처럼 날짜에 따라 값이 바뀐다고 공지된 경우(2027-01-01 인상)가 있어 파일 이름에 날짜를 넣었다.

## 한계
- 토큰 수는 세지 않고 정한 가정값이다. 실제 값은 응답의 usage나 토큰 세기 기능으로 확인한다.
- 캐시 흉내는 "처음부터 똑같은 블록까지만 다시 쓴다", "읽으면 유지 시간이 다시 시작된다", "최소 토큰 미만은 캐시하지 않는다"만 담았다. 실제 서비스의 캐시는 서버 사정으로 더 일찍 지워질 수 있고, Anthropic은 캐시 지점마다 20블록까지만 거슬러 찾는다.
- Gemini는 implicit 캐시의 쓰기 할증·저장 요금·유지 시간을 문서에서 찾지 못해 "할증 없음, 저장 요금 없음, 매번 적중"으로 가정했다.
- SDK 재시도 대기 시간(0.5초 × 2^k)은 문서에 정확한 값이 없어 정한 값이다.

확인일 2026-10-10.
