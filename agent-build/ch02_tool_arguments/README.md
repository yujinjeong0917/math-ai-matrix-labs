# 2장 · 도구에 넘기는 값이 형식은 맞는데 뜻이 틀리면 누가 잡나요?

모델이 만들었다고 치는 `issue_refund` 호출 30개(`calls.json`, 고정)를 스키마 검사와 의미 검사에 차례로 넣고, 무엇이 어디서 걸리는지 세요. 호출마다 `intended`(고객이 실제로 원한 값)를 함께 적어 두어 채점에만 써요. 표준 라이브러리만 쓰고 난수가 없어요.

## 실행

```bash
python3 tool_arguments.py
python3 -m unittest -q
```

## 기대 출력

```
호출 30 잘못된 호출 15
  통과(정상) 15
  형식 오류로 걸림 6
  의미 오류로 걸림 5
  조용한 오류 4
의미 검사 없이 실행될 잘못된 호출 9
조용한 오류의 호출 번호 ['c27', 'c28', 'c29', 'c30']
```

## 확인하지 못하는 것

- 실제 모델이 스키마를 얼마나 지키는지. 호출 30개는 만들어 둔 목록이에요.
- 스키마 검사기는 필수 값, 자료형, 허용 목록, 주문번호 모양, 추가 값 금지만 흉내 낸 최소 검사기이고 JSON Schema 전체를 구현하지 않았어요.
- 마지막 4개(c27~c30)는 어떤 검사로도 걸리지 않아요. 고객의 의도를 아는 쪽(사람, 되묻기)이 필요한데 이 코드는 그 부분을 만들지 않았어요.
