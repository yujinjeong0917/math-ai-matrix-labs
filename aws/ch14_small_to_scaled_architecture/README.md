# 14장 · 하루 20건의 첫 구성과 하루 2만 건의 성장 구성

같은 문의 답변 모델을 하루 20건과 하루 2만 건에서 비교합니다. 가격 대신 작업 시간·필요한 작업자 수·몰릴 때의 대기 시간을 계산하고, 그 숫자가 어떤 구성 요소를 요구하는지 판단합니다. AWS 계정이 필요 없습니다.

## 실행

```bash
python3 architecture_growth.py scenario.json
python3 -m unittest -q
```

## 기대 출력

| | 하루 20건 | 하루 2만 건 |
|---|---|---|
| 월 요청 | 600건 | 600,000건 |
| 월 계산 시간 | 5시간 | 5,000시간 |
| 평균 기준 작업자 | 1개 | 7개 |
| 몰릴 때(하루의 10%가 1시간 안에, 허용 대기 3,600초) 작업자 | 1개 | 18개 |
| 작업자 1개일 때 몰린 요청의 마지막 완료 | 150초 | 60,090초(16.7시간) |
| 평균 기준 작업자일 때 마지막 완료 | 150초 | 8,670초(허용 3,600초 초과) |
| 몰릴 때 기준 작업자일 때 마지막 완료 | 150초 | 3,450초(허용 이내) |
| 작업자 1개일 때 하루에 밀리는 작업 | 0초 | 513,600초(5.9일치) |
| 몰릴 때 기준으로 항상 켜 둔 시간 | 720시간 | 12,960시간 |
| 몰릴 때 기준으로 고정했을 때 가동률 | 0.7% | 38.6% |

구성 요소는 20건에서 보관·권한·경보·0에서 켜는 규칙 4개, 2만 건에서 대기열·밀린 건수 기준 확장·중복 방지·트래픽 나누기가 더해집니다.

## 본문에서 쓰는 말

- 작업자: 모델을 불러 두고 한 번에 한 건씩 처리하는 서버 1대(AWS 문서의 인스턴스).
- 시작 90초: 꺼진 작업자가 켜져 모델을 불러오기까지의 시간. 켜질 때 한 번만 더합니다(`startup_seconds`).
- 허용 대기: 몰림의 마지막 요청까지 끝나야 하는 마감(`acceptable_wait_seconds`). 3,600초는 예시값입니다.
- 몰림: 하루 요청의 10%가 1시간 안에 오는 구간. 계산은 한꺼번에 도착해 모두 꺼진 채 함께 시작한다고 가정합니다.

## 시나리오를 바꿀 때

건당 시간을 60초로 바꾸면 일의 양(1,200,000초)과 평균 작업자(14개)는 두 배가 되지만, 시작 90초는 그대로라서 1개로 2,000건을 끝내는 시간은 120,090초, 몰릴 때 작업자는 35개입니다(36개가 아님). 허용 대기를 300초로 줄이면 286개(월 205,920시간)입니다. 평균 7개만 항상 켜 두면 가동률은 99.2%지만 마지막 완료가 8,670초입니다.

## 이 실습이 확인하지 못하는 것

- 실제 비용. 단가를 쓰지 않습니다.
- 몰리는 비율(10%)과 시간(1시간), 건당 30초, 시작 90초는 모두 예시용 가정입니다. 내 로그로 바꿔야 합니다.
- 작업자 1개가 한 번에 한 건만 처리한다고 단순화했습니다. 배치 처리나 한 작업자의 동시 처리는 다루지 않습니다.
- 서비스별 한도와 지원 기능은 4장과 13장의 공식 문서 확인에서 다룹니다.
