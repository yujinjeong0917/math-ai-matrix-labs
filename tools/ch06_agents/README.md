# 6장. 에이전트에게 맡기면 어디서 멈출까 (`ch06_agents`)

웹 챕터: `math-ai-matrix/tracks/tools/06-agents.html`

관통 프로젝트(가상의 작은 팀이 만드는 "주간 고객 문의 요약 보고서")의 한 주 반복(5장의 Notion 2번·Figma 4번 읽기, 세기, 인용 모으기, 2·3장의 보고서 절 12개, 이 장에서 더한 페이지 만들기와 팀 채널 알림, 모두 22단계)을 워크플로(정해진 순서)와 에이전트(다음 행동을 모델이 고름)로 돌려, 단계가 길어질 때 성공률이 어떻게 줄고 확인 지점·다시 하기·사람 승인이 무엇을 바꾸는지 네트워크·API 키 없이 재현한다.

1. 단계 하나의 성공 확률 p로 n단계가 모두 옳을 확률 p^n을 분수로 계산한다.
2. 단계마다 검증 테스트(잡을 확률 d)와 다시 하기(최대 k번)를 붙였을 때 "끝까지 옳음 / 틀린 채 끝남 / 멈춤" 세 갈래를 닫힌 식으로 구하고, 되돌리기 어려운 단계 앞의 사람 승인(알아챌 확률 h)을 더한다.
3. 3장 도구 호출 고리 모양을 옮긴 가짜 에이전트(다음 행동을 q의 확률로 옳게 고름)와 정해진 순서의 워크플로를 보통 주(문의 2쪽)·이상한 주(3쪽)에서 비교한다.
4. 같은 값을 고정 시드 시뮬레이션(2만 주)과 시도 경로를 모두 펼친 계산으로 대조한다.
5. 에이전트 제품의 사실(무엇을 하나, 어디서 도나, 어떻게 허락을 받나, 회사가 밝힌 수치)을 날짜가 붙은 파일에 모으고, 직접 만든 설정 예시(Claude Code `settings.json`, Codex `config.toml`)의 키가 문서 값과 맞는지 테스트한다.

## 실행
```bash
uv run python tools/ch06_agents/experiments.py   # results/ch06.json 갱신
uv run pytest -q tools/ch06_agents
```
표준 라이브러리만 쓴다(fractions, random, tomllib). 모델·Notion·Figma를 부르지 않는다.

## 한계
- p, q, d, h, k, 이상한 주 비율은 모두 정한 가정값이다. 어떤 제품의 실측 성공률이 아니다.
- 단계끼리 서로 영향이 없다고 본다(독립). 실제로는 앞 단계의 틀림이 뒤 단계를 더 틀리게 하거나, 같은 원인으로 여러 단계가 함께 틀린다.
- 에이전트가 잘못 고르면 "그 일을 건너뜀"으로만 흉내 냈다. 같은 일을 되풀이하거나 엉뚱한 도구를 부르는 실패는 넣지 않았다.
- 검증 테스트가 잡을 확률 d를 모든 단계에 같게 두었다. 실제로는 "Notion을 다 읽었나"처럼 늘 잡는 확인과, 글의 질처럼 잡기 어려운 확인이 섞여 있다.
