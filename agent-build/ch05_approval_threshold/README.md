# 5장 · 금액이 얼마부터 사람에게 물어야 하나요?

환불 요청 100건(`refund_requests.json`, 가상 금액, 원)에 승인 문턱을 바꿔 가며 사람 승인 건수와 승인 없이 나가는 금액을 세고, 같은 주문의 환불을 여러 요청으로 쪼갰을 때 문턱이 뚫리는지 확인하는 장난감 실험이에요. 파이썬 표준 라이브러리만 쓰고 난수가 없어서 몇 번을 돌려도 같은 값이 나와요.

## 실행

```bash
python3 approval_threshold.py      # 문턱별 표와 쪼개기 결과 출력
python3 -m unittest -v             # 시험 9개
```

## 기대 출력(문턱 50,000원 줄과 쪼개기)

| 문턱(원) | 승인 건수 | 승인 없이 나가는 합계(원) | 승인 없이 나가는 최대(원) | 승인자 시간(분) |
|---|---|---|---|---|
| 10,000 | 90 | 79,000 | 10,000 | 270 |
| 20,000 | 68 | 426,000 | 20,000 | 204 |
| 30,000 | 51 | 863,000 | 30,000 | 153 |
| 50,000 | 31 | 1,652,000 | 50,000 | 93 |
| 80,000 | 14 | 2,753,000 | 79,000 | 42 |
| 100,000 | 9 | 3,191,000 | 95,000 | 27 |
| 150,000 | 2 | 4,042,000 | 134,000 | 6 |
| 250,000 | 0 | 4,423,000 | 217,000 | 0 |

쪼개기(문턱 50,000원, 6개 주문, 요청 합계 669,000원): 요청 한 건씩 검사하면 승인 없이 669,000원이 나가고, 주문 누적 합계로 검사하면 263,000원이 나가며 10건이 사람에게 가요.

## 가정한 값

승인 한 건을 보는 시간 3분, 승인 대기 시간 30분은 가상 가정이에요(`MINUTES_PER_APPROVAL`, `WAIT_PER_APPROVAL`).

## 이 실습이 확인하지 못하는 것

실제 승인자가 얼마나 주의 깊게 보는지(피로), 실제 환불 금액의 분포, 주문이 아닌 단위(고객, 하루)로 쪼개는 경우, 실제 모델이 금액을 어떻게 나누는지는 재지 않았어요.
