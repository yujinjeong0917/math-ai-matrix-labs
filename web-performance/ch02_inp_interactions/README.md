# 2장 실습: 탭 지연 세 부분과 INP

가상 방문의 탭마다 입력 지연, 처리 시간, 표시 지연을 더해 지연을 구하고, 방문 하나의 INP와 방문 8번의 75번째 백분위를 계산한다. 로딩 표시를 곧바로 그린 결제 탭에서 응답 대기 6000ms가 탭 지연에 들어오지 않는 것도 계산한다. 모든 시간은 가상, 예시용이다.

- 실행: `python3 inp_interactions.py`, 테스트: `python3 -m unittest -v` (표준 라이브러리만, 난수 없음)
- 기준값 출처: web.dev 문서(2026-11-20 확인, 정리해서 옮김, 문장 인용 아님). 4장의 논문 값은 저자 공개본 PDF(2026-11-20 확인).

손계산: 20+60+30=110, 15+40+25=80, 30+90+50=170, 40+120+60=220, 110+180+90=380ms. 5번이면 빼는 것이 없어 INP는 380ms. 60번 방문은 60 // 50 = 1개를 빼서 380ms가 빠지고 INP는 220ms. 방문 8번 INP를 세우면 90 110 140 150 160 180 220 380이고 올림(0.75 x 8) = 6번째 180ms. 결제 탭 10+30+20=60ms, 응답 6000ms를 더하면 6060ms.

기대 출력:
```
[탭] 정렬 탭: 20+60+30 = 110ms
[탭] 필터 열기: 15+40+25 = 80ms
[탭] 상품 담기: 30+90+50 = 170ms
[탭] 쿠폰 입력: 40+120+60 = 220ms
[탭] 결제하기: 110+180+90 = 380ms
[방문 A] 상호작용 5번, 빼는 개수 0, INP 380ms(개선 필요)
[긴 방문] 상호작용 60번, 빼는 개수 1, 가장 느린 탭 380ms, INP 220ms(개선 필요)
[결제 탭] 눌러서 다음 화면까지 10+30+20 = 60ms(좋음), 결제 응답까지 6000ms 더 기다림, 합 6060ms
[점검 1] 25+100+40 = 165ms(좋음)
[점검 2] 상호작용 110번이면 빼는 개수 2
[점검 3] 탭 60ms, 응답 대기 3000ms, INP에 들어가는 값 60ms
[방문 8번] 정렬 [90, 110, 140, 150, 160, 180, 220, 380]
[방문 8번] ceil(0.75 x 8) = 6번째 값 = INP p75 180ms(좋음), 200ms 초과 방문 2번(25%)
```

확인하지 못하는 것: 50번당 하나를 무시하는 규칙은 문서 요약 기준이고 경계(50번째에서 몇 개를 빼는지)는 원문으로 확인해야 한다. 이 실습은 상호작용 수를 50으로 나눈 몫만큼 뺀다고 가정했다. INP가 다음 프레임까지만 잰다는 정의를 가상 숫자에 대 본 것이고, 결과 화면을 어느 지표가 다루는지는 확인하지 못했다. 사용자가 느낀 시간은 계산하지 않는다.
