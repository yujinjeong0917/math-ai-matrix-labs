환불 문의 한 건을 에이전트가 처리할 때 모델 호출 수, 입력 토큰 누적, 대기 시간을 계산식으로 센다. 모든 입력값(시스템 프롬프트 길이, 도구 결과 길이, 도구 응답 시간, 모델 대기 시간 계수)은 `cost_latency.py` 위쪽의 가상 값이다. 단가는 코드에 고정하지 않고 `cost_units(결과, 입력 단가, 출력 단가)`에 부르는 쪽이 넣는다. 파이썬 표준 라이브러리만 쓰고 난수는 없다.

## 실행

```bash
python3 cost_latency.py          # 결과를 JSON으로 출력
python3 -m unittest -v           # 테스트 7개
```

## 기대 출력(핵심)

| 흐름 | 모델 호출 | 입력 토큰 합 | 출력 토큰 합 | 대기(초, 가상) |
|---|---|---|---|---|
| 직렬 조회 3번 + 환불 + 안내 | 5 | 6520 | 280 | 13.008 |
| 조회 3개를 한 호출에서 병렬 | 3 | 4260 | 280 | 10.604 |

- 직렬 흐름에 사람 승인 대기 120초를 더하면 133.008초다(5장 값을 더하는 자리).
- 환불 도구가 계속 오류를 돌려주는 문의 한 건: 단계 상한 10, 20, 50에서 입력 토큰 합은 16350, 42050, 167150이고, 정상 문의(6520) 대비 2.51배, 6.45배, 25.64배다.
- 가상 문의 20건(환불 오류 횟수: 0회 12건, 1회 4건, 2회 2건, 5회 1건, 끝까지 오류 1건)에서 단계 상한별로 안내까지 가지 못하고 멈춘 건수: 상한 4는 20건, 5는 8건, 6은 4건, 8은 2건, 10은 1건, 20은 1건.

## 이 실습이 확인하지 못하는 것

실제 요금과 실제 응답 시간은 재지 않는다. 입력 토큰, 대기 시간 계수는 설명용 가상 값이다. 프롬프트 캐싱, 스트리밍, 모델별 도구 사용 토큰 차이는 반영하지 않는다. 가짜 모델이라 실제 모델이 오류를 만났을 때 같은 호출을 반복할지는 알 수 없다.
