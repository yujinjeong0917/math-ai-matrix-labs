# 개발자에게 넘기기 전 체크리스트 (관통 프로젝트 "동네 스터디룸 예약")

확인일 2026-10-08. 2장의 `figma_file_spec.md`를 따른 파일을 전제로 한다. 한 줄이라도 비어 있으면 넘기지 않는다.

## 1. 화면 x 상태 표 (16칸을 모두 채운다)
| 화면 | 기본 | 오류 | 빈 | 로딩 |
|---|---|---|---|---|
| S01 목록 | 그림 | 그림(불러오기 실패) | 그림(조건에 맞는 방 없음) | 그림(회색 셀 3개) |
| S02 상세 | 그림 | 그림(불러오기 실패) | 이 화면엔 없음: 방을 눌러야 열림 | 그림(사진 자리 회색 상자) |
| S03 예약 | 그림(필수 입력 전 버튼 비활성 포함) | 그림(시간 겹침) | 이 화면엔 없음: 비어 있는 상태가 곧 기본 | 그림(버튼 비활성 + '예약 중…') |
| S04 완료 | 그림 | 이 화면엔 없음: 확정 응답 뒤에만 열림 | 이 화면엔 없음: 예약이 항상 하나 있음 | 이 화면엔 없음: 확정 응답과 함께 열림 |

- 칸마다 "그림"이면 프레임 이름(`S03_예약_오류`), "이 화면엔 없음"이면 이유 한 줄.
- 완결성 = 그린 칸 / 필요한 칸. 이 프로젝트는 11 / 11이어야 한다.

## 2. 치수·글자·색
- 여백·간격은 숫자 대신 간격 값 이름으로 적는다(예: `space.4 = 16`).
- 글자 크기와 색은 변수·스타일 이름으로 지정한다(`font.title`, `color.primary`).
- 이미지를 함께 보낼 때는 몇 배로 내보냈는지 적는다(2배면 픽셀 수를 2로 나눠야 CSS px).

## 3. 문구
- 모든 문구가 최종본이다. 문구의 기준 원본은 Notion 스펙 페이지이고, 프레임에 그 링크를 붙인다.
- 오류·빈 상태 문구도 여기에 포함한다.

## 4. 동작(프로토타입)
- 전환 18개를 `03 Prototype`에 연결한다(`data/transitions.json`).
- 검사: 시작(S01 로딩)에서 닿지 않는 상태 0개, 막다른 상태 0개, 오류에서 오류가 아닌 상태로 돌아갈 길이 없는 상태 0개.
  `productivity_ch03_checks.check_bfs()`가 같은 검사를 한다.
- 뒤로 가기 뒤 스크롤 위치, 오류 뒤 입력값 유지처럼 그림으로 안 보이는 규칙은 연결 이름이나 주석에 적는다.

## 5. 접근성
- 누르는 것의 터치 영역 크기를 적는다. 아이콘만 그렸으면 실제 누르는 영역 프레임을 따로 둔다.
  기준: WCAG 2.2 2.5.8(AA) 24 x 24 CSS px 이상(예외 있음), 2.5.5(AAA) 44 x 44 CSS px 이상.
- 글자색/배경색 짝의 대비를 적는다. 기준: WCAG 2.2 1.4.3(AA) 4.5:1 이상(큰 글자 3:1, 비활성 요소 등 예외).

## 6. 링크와 넘기는 방식
- 관련 Notion 결정·스펙 페이지 링크를 프레임에 붙인다.
- 넘기는 방식: Dev Mode를 쓸 수 있는 요금제인지, 보기 권한 + 이 체크리스트로 넘기는지 적는다.
  Dev Mode가 있어도 1~5는 그대로 채운다. Dev Mode는 그린 것을 정확히 보여 줄 뿐, 그리지 않은 상태를 만들어 주지 않는다.
