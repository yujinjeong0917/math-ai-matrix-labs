# 9장. 파인튜닝 결과 평가: 원래 모델보다 나아졌나 (`ch09_evaluate`)

웹 챕터: `math-ai-matrix/tracks/finetune/09-evaluate.html`

관통 프로젝트(작은 팀이 고객 문의 답변 초안을 우리 말투로 쓰는 모델 만들기)에서, 8장에서 학습한 모델이 원래 모델보다 정말 나아졌는지 재는 방법을 GPU 없이 연습하고, 오너가 직접 돌릴 Colab 노트북을 함께 둔다. **손실 곡선과 채점 데이터는 모두 가상이다. 실제 학습 결과 숫자가 아니다.**

1. 손실 곡선: 식으로 만든 가상 학습·검증 손실(6에폭, 17스텝마다 평가)에서 가장 낮은 지점과 멈출 지점을 찾는다. 조기 종료 규칙은 transformers v5.19.0 `EarlyStoppingCallback.check_metric_value`와 Trainer의 호출 순서(콜백이 먼저, best 갱신이 나중)를 그대로 옮겼다. 8장 노트북 설정(34스텝마다, 3에폭)으로는 점이 3개뿐이라는 것, 학습 데이터와 닮은 검증 세트는 꺾이지 않는다는 것도 본다.
2. 채점: 1장 평가 세트(문의 40건)에 대한 가상 답을 재료(`data/answer_bank.json`)와 모델별 조합(`data/score_sheet.json`)으로 조립하고, 정확 일치·정규화 일치·규칙 검사·사람 채점표로 각각 센다. 규칙 검사가 놓치는 곳(말투, 엉뚱한 답)과 잘못 떨어뜨리는 곳(같은 뜻의 다른 낱말)을 문항 번호로 보인다.
3. 실패 종류별 바뀜: 기준 모델 → 새 모델에서 K/F/T/I/R/OK마다 고친 문항과 나빠진 문항, 1장 모형의 예상과 나란히. 일반 문항 20개로 잊어버림을 본다. 일반 문항은 쇼핑몰 지시 대신 중립 system(`probe_system`)으로 두 모델에 똑같이 묻는다(지시가 양식을 끌어오는 것과 어댑터가 잊은 것을 섞지 않으려고). 규칙 검사는 사람 판정을 정답으로 둔 혼동행렬(정밀도·재현율)로도 센다.
4. 장난감 채점자: 사람 판정이 같을 때 먼저 보여 준 답을 고르는 채점자로, 순서를 바꾸면 승률이 얼마나 달라지는지 센다.
5. 우연인가: 짝지은 부트스트랩 1,000번(모델 평가 트랙 7장과 같은 방식)과 엇갈린 문항의 정확한 부호 검정, 같은 비율이면 문항이 몇 개 있어야 갈리는지.

## 실행
```bash
uv run python finetune/ch09_evaluate/experiments.py   # results/ch09.json 갱신
uv run pytest -q finetune/ch09_evaluate
```
`ft_ch09_eval.py`는 표준 라이브러리만 쓴다. 테스트는 백분위수·부트스트랩을 NumPy로 한 번 더 계산해 대조한다. 무작위는 `random.Random(seed)`로 고정해 결과가 바이트까지 같다.

## Colab 노트북
`colab/ch09_evaluate_t4.ipynb`. 8장 노트북을 먼저 끝까지 돌려 `ch08_lora`와 `outputs/checkpoint-*/trainer_state.json`이 있어야 한다. **작성자는 이 노트북을 돌려 보지 않았다**(출력 칸이 비어 있다). 기준 모델은 같은 4bit 모델에서 어댑터만 끈 것(`model.disable_adapter()`)이다. Unsloth의 `for_inference`와 함께 쓸 때 어댑터가 제대로 꺼지는지는 확인하지 못했고([확인 필요]), 노트북 9번 칸이 두 모델 답이 모두 같은지 세어 알려 준다. 사람 채점은 A/B로 가린 CSV로 한다.

## 한계
- 곡선은 지수 감소 + 제곱으로 오르는 항으로 만든 모양이다. 실제 곡선은 학습률 일정, 데이터, 에폭 경계에 따라 다르게 생긴다.
- 채점 데이터는 일부러 만든 것이라, 비율(예: 규칙 검사가 놓친 3건)은 방법을 보이는 예일 뿐 실제 모델에서 얼마나 자주 그런지는 알려 주지 않는다.
- 사람 채점은 한 사람이 일곱 칸을 매긴다고 두었다. 실제로는 두 사람이 따로 매겨 얼마나 일치하는지 보는 편이 좋다.
- 장난감 채점자는 순서 치우침만 흉내 낸다. 길이 치우침, 자기 답 편들기 같은 다른 치우침은 넣지 않았다.
- 부트스트랩은 문항이 서로 독립이라고 본다. 같은 주제의 문항이 몰려 있으면 구간이 실제보다 좁을 수 있다.
