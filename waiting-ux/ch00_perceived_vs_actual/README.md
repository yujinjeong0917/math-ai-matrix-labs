가상의 어느 페이지를 열 때마다 잰 LCP(페이지를 열 때 가장 큰 내용이 그려지기까지의 시간) 10번 값이 있다고 하고, 평균, 가운데값, 75번째 백분위를 직접 계산해 web.dev의 "좋음" 기준과 대조한다. 모든 숫자는 가상, 예시용이다.

- 실행: `python3 delay_percentile.py`, 테스트: `python3 -m unittest -v` (표준 라이브러리만)
- 기준값 출처: web.dev, Web Vitals (https://web.dev/articles/vitals), 2026-11-18 확인. LCP 2.5초 이내, INP 200ms 이하, 75번째 백분위로 판단(코드 상수에는 CLS 0.1도 적어 두었으나 본문은 쓰지 않음). 문서 갱신일 2024-10-31.

손계산(A): 정렬하면 1.7 1.8 1.9 2.0 2.1 2.2 2.3 2.4 3.6 4.8. 위치 0.75×9=6.75이므로 2.3과 2.4 사이의 75% 지점, 2.375초.

표본 C(가상): 1.2 1.3 1.4 1.5 1.6 1.8 2.7 2.9 3.1 3.5. 합 21.0이라 평균 2.10초(기준 안), 위치 6.75는 2.7과 2.9 사이의 75% 지점이라 2.85초(기준 밖). 방문의 40%가 2.5초를 넘었다. 평균은 통과인데 75번째 백분위는 탈락하는 예이다.

기대 출력:
```
[A] 평균 2.48초(기준 안), 가운데값 2.150초, p75(선형) 2.375초, p75(순위) 2.4초, 2.5초 초과 20%, p75 판정 좋음
[B] 평균 2.67초(기준 밖), 가운데값 2.650초, p75(선형) 2.950초, p75(순위) 3.0초, 2.5초 초과 60%, p75 판정 기준 밖
[C] 평균 2.10초(기준 안), 가운데값 1.700초, p75(선형) 2.850초, p75(순위) 2.9초, 2.5초 초과 40%, p75 판정 기준 밖
[Tan 사려 깊음] 2초 5.76(SD 1.18, n=79), 9초 6.09(SD 0.90, n=80): 차이 0.33점, 합동 SD 1.05, d 0.31
[Tan 지연을 느꼈다고 답한 비율] 2초 21/79=26.6%, 9초 53/80=66.3%, 20초 66/81=81.5%
60Hz 한 프레임 16.7ms
200ms는 60Hz 화면에서 12프레임
```

Tan 줄: 사려 깊음 평균과 SD는 논문이 적은 값, 인원은 논문의 칸별 인원(Creation 41/42/41, Advice 38/38/40)을 과제 유형끼리 합친 79/80/81명이고, d는 두 집단 합동 SD로 이 실습이 계산한 값이다. 비율은 합친 인원으로 다시 나눈 것이다.

확인하지 못하는 것: 사람이 느낀 시간, 만족, 이탈. web.dev가 백분위 계산 방식(선형 보간인지 순위인지)을 적었는지는 확인하지 못해 두 방식을 모두 보였다.
