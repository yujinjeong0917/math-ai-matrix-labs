# 2장 실습: 단계별 맡김 수준을 점검 규칙 두 개로 확인하기

가상 환불 처리의 여섯 단계를 Parasuraman 외(2000)의 자동화 유형 네 가지(정보 획득, 정보 분석, 결정, 행동)로 나누고, 세 가지 맡김 수준을 정한 설계안 세 개를 점검 규칙 두 개로 확인한다. 모든 숫자는 가상, 예시용이거나 논문 보고값이다.

- 실행: `python3 delegation_check.py`, 테스트: `python3 -m unittest -v`
- 출처: doi.org/10.1109/3468.844354 (본문 사본 열람 2026-11-20, 서지 확인 2026-11-20). 논문은 비공식 사본 텍스트로 읽었고 표 I과 그림은 보지 못했다.

기대 출력:
```
[1] 단계와 자동화 유형
  주문 조회 | 정보 획득 | 되돌릴 수 있음
  규정 대조와 금액 계산 | 정보 분석 | 되돌릴 수 있음
  환불 승인 또는 거절 고르기 | 결정 | 되돌릴 수 있음
  환불 지급 | 행동 | 되돌릴 수 없음
  고객 안내 전송 | 행동 | 되돌릴 수 없음
  상담 기록 | 행동 | 되돌릴 수 있음
[2] 설계안별 경고(W1 되돌릴 수 없는 단계를 확인 없이 실행, W2 결정과 행동을 안 보이게 맡김)
  A 모두 맡기고 요약만 보기: W1 2개, W2 4개, 합 6개
  B 결정과 지급과 안내는 사람이 확정: W1 0개, W2 0개, 합 0개
  C 결정은 맡기고 지급은 확정: W1 1개, W2 0개, 합 1개
[3] A의 경고 단계
  W2 환불 승인 또는 거절 고르기
  W1 환불 지급
  W2 환불 지급
  W1 고객 안내 전송
  W2 고객 안내 전송
  W2 상담 기록
[4] A에서 B로 바꾼 단계 4개: 환불 승인 또는 거절 고르기, 환불 지급, 고객 안내 전송, 상담 기록
[5] 단계 6개를 유형 4개와 수준 3개로 나누면 칸 12개
```

확인하지 못하는 것: 맡김 수준 세 가지와 규칙 W1, W2는 이 장이 만든 단순화이고 논문이 제시한 기준이 아니다. 논문의 근거 사례는 항공 교통 관제 등이고 LLM 화면에서 이 점검이 옳다는 것을 보이지 않는다.
