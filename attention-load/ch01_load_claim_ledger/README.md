# 1장 실습: 화면 설계 주장의 말투와 출처 표시를 나눠 세기

화면 설계 문서에 흔한 가상 주장 7개를 읽어 "숫자 규칙", "절대 표현", 출처 표시(리뷰가 소개한 틀 / 설계자 추측 / 없음)로 나눠 센다. 이 코드는 말투와 출처 표시만 본다. 주장이 맞는지 판정하지 않는다.

- 입력: `claims.json` (가상, 예시용. 자기 팀의 문장으로 바꿔 보면 된다)
- 실행: `python3 claim_ledger.py`, 테스트: `python3 -m unittest -v`
- 규칙: 숫자 단위(개, %, 초 등)가 보이면 출처와 상관없이 "숫자 규칙: 읽은 근거 없음", "항상/반드시/절대" 같은 말이 보이면 "절대 표현: 읽은 근거 없음"으로 센다.

기대 출력:
```
[1] 주장 7개
  1. 한 화면에는 선택지를 5개 이하로 둔다 -> 숫자 규칙: 읽은 근거 없음
  2. 같은 안내 문구가 단골 구매자에게는 군더더기가 될 수 있다 -> 설계자 추측
  3. 배송 안내 문구는 항상 접어 둔다 -> 절대 표현: 읽은 근거 없음
  4. 화면 요소를 3개 줄이면 머리 부담이 20% 줄어든다 -> 숫자 규칙: 읽은 근거 없음
  5. 사람의 작업 기억 용량에는 한계가 있다 -> 이론 틀 소개 수준
  6. 처음 구매하는 사람에게는 지금 단계에 필요한 것만 보여 주는 편이 도울 수 있다 -> 설계자 추측
  7. 알림 배지가 있으면 주문을 더 빨리 끝낸다 -> 출처 없음
[2] 분류별 개수: 숫자 규칙: 읽은 근거 없음 2, 절대 표현: 읽은 근거 없음 1, 이론 틀 소개 수준 1, 설계자 추측 2, 출처 없음 1
```

확인하지 못하는 것: "읽은 근거 없음"은 그 주장이 틀렸다는 뜻이 아니라 이 트랙이 읽은 자료로는 받쳐 줄 수 없다는 뜻이다. 정규식은 말투만 보므로 숫자가 없어도 근거 없는 주장은 통과한다. 인지 부하 이론이 화면 UI에서 성립하는지는 이 코드도, 이 트랙도 확인하지 못한다.
